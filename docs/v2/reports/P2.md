## The browser agent, step by step

1. **The coordinator queues it.** In a DM, v1 Juno runs
   `python tools/browser_queue.py add --url <form> --task ... --value "Field=value" ...`. The queue rejects:
   - http pages
   - a value that looks like a card number (Luhn check) or a Social Security number
   - a field named like a password, PIN, account number or ID
2. **The fill run.** The bridge's `browser_watcher` thread starts a separate `claude -p` (Sonnet, up to 40 turns and
   $1.50):
   - `--tools ""`, so no built-in tools
   - `--mcp-config`, so only the Playwright server, and `--strict-mcp-config`, so nothing else
   - `--setting-sources user`, so no CLAUDE.md, memory or connectors
   - `--settings`, which loads the gate hook. It was checked on 2026-11-12 that hooks load this way.

   The browser is Playwright's bundled Chromium (never his Chrome), headless, in its own profile at
   `state/browser/profile`. Page-registered tools are off (`webmcp: false`). The run fills the form, doesn't submit,
   and returns JSON listing the site, every field and value, and the button it would press.
3. **The card.** It shows Site, Values, Button and "a sent form can't be taken back", with **Yes, submit** and
   **Not now**. It has no Always button and is never auto-approved. The tap is bound to the site, the page, every
   value and the button (payload hash).
4. **The submit run.** After the tap, the bridge writes a one-time pass (15 minutes, this approval only, these values
   only) and runs the agent again. The agent:
   - fills the same values and presses that button
   - may press through later pages that ask for nothing new (an instructions page)
   - stops at anything new, a login, a payment or a CAPTCHA

   Success is claimed only when the page shows a confirmation; Michael gets its text and any reference number, and
   one screenshot of it lands in `state/browser/out` for the log. The bridge adds a 14-day follow-up for their answer. The pass is deleted after the run.
5. **The gate** (`.claude/hooks/gate_browser.py`) checks every Playwright call:
   - **Tools:** only the listed ones. JavaScript, file upload, routing, cookies, storage and tabs are never allowed.
   - **Navigation:** https on the request's sites only.
   - **Values:** no secret is ever typed.
   - **Buttons:** buy, pay, checkout, sign up, create account and log in are never pressed.
   - **Fill run:** no Enter key, and no click once a value is in.
   - **Submit run:** needs the pass, and may type only the values on the card.

## Known limits

- The gate can't see the page. It judges a click by the element description the model gives, which is why a fill run
  allows no clicks at all once a value is in. Checkboxes, radios and dropdowns go through `browser_fill_form`.
- A form that needs a click before its first field (a "Start claim" button) works. A form with a dynamic widget that
  only a click can set, after the first value is in, stops the run and says so.
- Playwright's `allowedOrigins` is not used (DV21); the gate is the navigation check.
- One browser run at a time: runs take the bridge's run lock, and the profile can serve only one browser.
