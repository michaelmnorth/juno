# P1 report · context engine (interim, 2026-11-10, branch `v2-p1`)

Built and tested on synthetic data. Real DMs have not run on it yet: that needs the runtime's own API key (O1).
Every chat stays on v1 until the owner says "use v2" in it.

## What was built

| Deliverable | Where | State |
|---|---|---|
| 1. Event queue and thread store | `v2/store.py` (SQLite at `state/v2.db`) | Done. Events deduped by Slack timestamp; threads keep summary, working set, taint, engine flag |
| 2. Tool registry | `v2/tools.py` | Done. 17 typed tools over the existing scripts (`v2/backend.py`), strict schemas, tiers, data classes, `returns_untrusted`, capped results |
| 3. Policy engine | `v2/policy.py` | Done. Tools per run, tiers, taint at call time, pause, input checks in code; T3 becomes a card built by code |
| 4. Router | `v2/router.py` | Done. One Haiku 5.5 structured call on the message and thread summary only; low confidence goes to `general` |
| 5. Assembler | `v2/assembler.py` | Done. Nine blocks in order, budgets, cache marks A and B (L2), operator facts as a mid-conversation system message, data delimited |
| 6. Lanes L1, L2 | `v2/lanes.py` | Done. Structured output both lanes; L2 loop bounded by the run's calls and dollars; refusal and max_tokens handled |
| 7. `reader` class | `v2/lanes.py` `read`, tool `mail_read` | Done. Typed fields enter the run untainted; the gist taints only when asked for |
| 8. Flag and errors | `gateway/slack_bridge.py` | Done. "use v2" / "use v1" per chat; a failure answers with a ref and no fallback |
| 9. Dialogue set | `evals/dialogues.py`, `evals/world.py`, `evals/run_dialogues.py` | 22 dialogues, graded in code. Not yet run on real models |

Tests: `tests/test_v2.py` (24) covers each "Done when" item that can be checked without real traffic: no shell, file
or HTTP tool; tainted run turns a hold into a card; sends are always cards built from the draft itself; a follow-up
14 hours later resolves "that" from the working set; duplicate Slack deliveries answered once; budget stops say what
was done; first request inside 8K with every block inside its budget. Whole suite: 369 passing.

## Tools

Ported: calendar (events, free, check, hold, undo hold, invite card, move card), mail (search, read through the
reader, draft, send card), people (lookup, contact email), reminders (add, list), notes (add, search).

Not ported, on purpose: health and the coach sheet, YouTube and the watch digest, finance, web research, lessons,
people-profile queueing, labels. The router sends those to a fixed reply that says to use v1.

## Decisions the build argues against

- None of D1 to D14. One finding for the taint rule: if every invite title tainted the thread, almost every
  calendar question would turn later holds into cards for a day. P1 taints only on invites someone else sent
  (`organizer_self`, added to `tools/gcal.py`). Watch the card count in the first week.

## Rollback

Say "use v1" in the chat. The v2 code only runs for a chat whose flag is v2.
